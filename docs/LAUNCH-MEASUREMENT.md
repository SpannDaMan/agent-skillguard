# Launch Measurement

GitHub stars are a visibility signal, not the product outcome. Skill Risk Check should be measured as an adoption and qualified-demand funnel.

## Funnel

1. Discovery: repository views and referral sources.
2. Evaluation: README engagement, clones, install attempts, demo runs, and documentation visits where observable.
3. Adoption: reproducible issues, feature requests, discussions, forks, and repeat contributors.
4. Quality signal: reports of useful findings, reviewed suppressions, documented false positives, and reproducible misses.
5. Sustainability: GitHub Sponsors activity and any later separately approved paid offering.

## Privacy boundary

Version 0.1.0 contains no plugin telemetry. Do not add background tracking or transmit scanned artifacts to measure usage. Prefer GitHub's aggregate repository metrics and voluntary user feedback. Any future opt-in telemetry requires a separate design, privacy review, and release decision.

## Review cadence

- Day 1: confirm links, install instructions, and visible repository metadata.
- Day 7: review referral sources, clones, issues, and confusion patterns.
- Day 30: decide whether to continue, revise positioning, expand the rule pack, or stop.

Do not use stars alone as the launch verdict.
